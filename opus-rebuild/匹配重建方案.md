## 目标

在 **不先堆规则、不上句向量** 的前提下，把口语泛化识别从「自证 89.7% / 留出 @1≈31%、近半返回空」拉到可验证的 held-out 指标；根因是单层「关键词长度求和」既当召回又当排序。

## 目标架构

```text
查询 → 规范化 / 同义扩展
     → 【召回层】字符 ngram + IDF/BM25 倒排，取 top-30，不设绝对阈值
     → 【重排层】槽位：action(动词) × object(对象) × modifier，动词高权
     → 【判决层】归一化分数 + top1/top2 margin → exact / weak / 兜底
     → 【兜底层】低置信不返回空，给大类候选（sys/net/docker/svc…）
```

## 已验证（只换打分、不动 213 条规则）

同一留出集 45 条，keywords+desc 做 2–3gram IDF 余弦：

| 指标 | 现状（求和 + t_weak=4） | 原型 |
|------|-------------------------|------|
| @1 | 31.1% | 42.2% |
| @3 | 44.4% | 55.6% |
| @10 | 48.9% | **82.2%** |

## 落地优先级

| 优先级 | 动作 | 预期 |
|--------|------|------|
| **P0** | **留出泛化基准**：人工 200+ 口语，禁止复用 keyword 字面；同时报 in-corpus 与 held-out | 指标能反映真实体验 |
| **P0** | 召回层换 IDF/BM25 归一化打分，去掉绝对阈值砍召回 | @10 ≈ 49% → 82%（已原型） |
| **P1** | schema 增加 `action` / `object`；重排时 action 不匹配降权 | 修「重启 nginx → 查看配置」 |
| **P1** | 阈值改相对判据（归一化分 + margin） | 少返回空；改规则不再全局漂移 |
| **P1** | 低置信兜底：大类候选 + 「你是不是想问」 | 空结果转为可用 |
| **P2** | jieba：内置轻量词典成主路径，或降为可选增强；**两路径同一套打分公式** | 结果可复现 |
| **P2** | `history.json`：query→用户选中 intent 进重排；离线挖长尾 | 替代纯手工枚举 |
| **P2** | 规则冲突检测：关键词高重叠告警 | 防新增压制老规则 |

## 明确不做（现阶段）

不上离线句向量 / embedding。P0/P1 吃完、held-out @1 约 70% 仍瓶颈时，再评估 BM25 + 轻量句向量混合检索。

## 建议实施顺序

1. 落 held-out 语料与双轨基准脚本（与现有 `bench_corpus.py` 并列，禁止混用）  
2. 召回层 IDF/BM25 替换求和打分  
3. action/object 重排 + margin 判决 + 大类兜底  
4. jieba 公式合一、反馈与冲突检测  

实施记录、实验数字、规则 schema 变更说明继续写在 `opus-rebuild/`，不要写进 `.docs` 变更记录或 `cloud_init`。
