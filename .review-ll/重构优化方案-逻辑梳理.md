# 重构优化方案 — 逻辑梳理

## 查询路径

```text
输入
  → preprocess(NFKC + 空白)
  → 同义词扩展查询串
  → 否定窗口检测
  → jieba tokens（停用词对规则词求差）或关键词+2-gram
  → 最长匹配去重打分；完整命中优先排序
  → Top-K；完整命中即使低于 T_WEAK 也标 weak 入围
  → extract 一次，按 rule.params 裁剪
  → fill_template 单遍 + 抽出值引号
  → 否定 / 危险抽出值写入 HitView
```

## 为何短词不再整句漏配

旧：短中文 ×0.6 后绝对阈值 4 直接淘汰。  
新：完整关键词命中 `has_full` → 参与 Top-K 排序（完整命中排在纯 ngram 前）；分数仍用于同档排序。

## 模板填充

```text
{path} 两侧已有引号 → 只转义内部引号
否则且 key ∈ QUOTE_KEYS → POSIX 单引号包裹
未抽出的 QUOTE_KEYS（如 `{path}`）同样包单引号，展示为 `dirname -- '{path}'`。
`java.app.scripts` 每步独立 shell，第三步用 `dirname -- '{path}'` 而不是上一步的 `$DIR`。
```

## reload

失败时恢复旧 `rules/adapt` 再把异常抛给 REPL 打印。

## 基准

`scripts/bench_corpus.py` 读语料表，写 `.docs/命中率对照-重构后.{md,json}`。
