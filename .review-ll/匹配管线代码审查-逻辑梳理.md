日期：2026-08-13
范围：`lch/preprocess.py`、`jieba_fallback.py`、`matcher.py`、`engine.py`、`extract.py`、`loader.py`、`pick.py`、`render.py`、`adapt.py`、`paths.py`、`formatter.py`

## P0（直接导致漏配 / 误配 / 错误命令）

### P0-1 短中文关键词双重降权 + 绝对阈值 → 整句漏配 [实测]

- 位置：`lch/matcher.py` L26-40（`_is_short_cjk`/`_keyword_weight` 封顶 1.5）、L79-80（子串命中再乘 0.6）、L171-172（绝对阈值 t_weak=4）
- 实测：`看下内存的占用情况` 在兜底路径 **0 命中**（"内存" 得分 1.5×0.6=0.9 + weight×0.1，远低于 4）。
- 影响：无 jieba 环境下，口语句中只含短关键词的查询大面积漏配；降短词权是为防串台，但把"唯一证据"也压死了。
- 建议：降权用于**排序**而非**淘汰**——阈值判定前按规则关键词权重和做覆盖率归一；或多个短词命中时取消二次 0.6；或加字符 2-gram 覆盖率兜底分（纯 Python 可实现）。

### P0-2 jieba 主路径：≤2 字 token 只允许完全相等，多字关键词无组合匹配

- 位置：`lch/matcher.py` L109-119

```110:119:lch/matcher.py
            if len(tl) <= 2:
                matched = tl == kw_l or tl == kw_ns
            else:
                matched = (
                    tl == kw_l
                    or tl in kw_l
```

- 影响：中文词绝大多数是 2 字。关键词 `内存占用` 无法被 tokens `[内存, 占用]` 命中（各自≠整词），只能靠 0.5 系数的**原文连续子串**辅分（L127-130），"内存**的**占用" 插一个字即彻底失效。凡是只配置 3-4 字短语关键词、没有同时列出 2 字子词的规则，在 jieba 主路径召回都严重受损。
- 建议：**加载期对每个 keyword 用 jieba 分词并缓存 token 集**，运行期按"关键词 token 覆盖率"打分（全覆盖≈全分、部分按比例，即加权 TF/coverage），不再依赖连续子串。同时把所有 keywords 经 `jieba.add_word()` 注入，保证整词切分一致性。

### P0-3 无否定词处理 [实测]

- 位置：`lch/matcher.py`、`lch/preprocess.py` 全文均无
- 实测：`不要重启nginx` → 命中 `nginx.restart`（weak 7.9）排第一。
- 影响：本工具在 agent 模式会给出可执行命令，否定语义误配 restart/kill 类意图属于安全风险。
- 建议：预处理检测否定副词（不要/别/不能/禁止/取消/千万别）邻接动词的窗口，命中时对相应规则降权或在结果上打"含否定语气"标记提示确认。

### P0-4 路径正则 `\w` 吞中文 → 渲染出错误命令 [实测]

- 位置：`lch/extract.py` L164 `re.findall(r"(/[\w./\-]+)", text)`
- 实测：`把/data权限改成755` → `path='/data权限改成755'`（Python `\w` 含 CJK），随后被填进 `chmod 755 /data权限改成755`。
- 建议：改为 `[A-Za-z0-9_./\-]+`；并加 `(?<!:)` 排除 URL（见 P1-8）。

### P0-5 owner / mode 提取冲突：`改成755` 同时提成属主 [实测]

- 位置：`lch/extract.py` L181-187

```181:184:lch/extract.py
        m = re.search(
            r"(?:改成|归还给|属主|所有者|拥有者)\s*"
            r"([A-Za-z0-9_.\-]+(?::[A-Za-z0-9_.\-]+)?)",
```

- 实测：`把/data权限改成755` → `{'mode':'755', 'owner':'755'}`。若规则 params 同时允许 owner（chown 类），会渲染 `chown 755 ...`。
- 建议：owner 分支排除纯数字/八进制值；"改成"触发词要求语境中有 属主/所有者/chown 才启用。

## P1（明显降低命中质量 / 健壮性）

### P1-1 keyword_weights 在 jieba 主路径被忽略

- 位置：`lch/matcher.py` L120-121 `score += max(len(token), 1) * 1.2` —— 主分只看 **token 长度**，与命中的是哪个 keyword、该 keyword 配置的权重无关；`keyword_weights`（rules.d 中实际使用 9 处）只作用于 0.5 系数的子串辅分（L130）。
- 影响：规则作者的调权手段在主路径失效。
- 建议：token 命中时按被命中 keyword 的 `_keyword_weight` 计分（或与 token 长度取组合）。

### P1-2 分数跨规则不可比、阈值语义漂移

- 位置：`lch/matcher.py` L101-130（逐 token、逐 keyword 累加，重叠不去重）、L171-172（绝对阈值）
- 影响：① 关键词互相重叠越多的规则天然分越高（`net.port.listen` 列了 11 个互相包含的 keyword，"端口占用" 同时命中 端口占用/端口/占用相关多个条目重复计分）；② 句子越长累计分越高，`confidence="exact"` 只是分数过 8，不代表精确；③ t_exact/t_weak 对不同规则/句长不公平。
- 建议：对同一文本区间的重叠命中按**最长匹配去重**只记一次；总分除以 `min(规则关键词权重和, 常数)` 做覆盖率归一后再比阈值；置信可加 Top1-Top2 分差（margin）维度。

### P1-3 归一化缺失（全半角 / 大小写 / 繁简）

- 位置：`lch/preprocess.py` L6-18 —— 仅映射全角数字 + 8 个标点；全角字母（ＮＧＩＮＸ）、全角？！～、繁体、统一小写都没做（lower 散落在 matcher 内逐次重复做）。
- 建议：`unicodedata.normalize("NFKC", text).casefold()`（纯 stdlib、零依赖）；繁简用内置单字映射表数据文件（离线、可选加载）。归一后 matcher 内的重复 lower 也可删除。

### P1-4 停用词表与规则关键词词表冲突

- 位置：`lch/jieba_fallback.py` L27-28 —— `查看`、`看看` 是停用词，但大量规则 keyword 是"查看ip""查端口"形态；jieba 切出"查看"即丢弃，token 路径永远贡献不了这类词。
- 建议：加载规则后用 keywords 词表对停用词求差集；配合 P0-2 的 `add_word` 方案。

### P1-5 同义词无机制

- 现状：全靠每条规则手工罗列变体（"端口占用/端口被谁占用/谁占用了端口"），必然覆盖不全且互相重叠加剧 P1-2。
- 建议：外置 `resources/dict/synonyms.json`（纯数据、离线），加载期做查询侧或关键词侧扩展；拼音容错可作为可选层（如 jieba 一样懒加载 pypinyin，缺失则跳过，不强制依赖）。

### P1-6 中文-ASCII 邻接处 `\b` / `\s+` 失效（extract 多处）[实测]

- `lch/extract.py` L22：`\b(\d{2,5})\b` —— `看下80被谁占用` 提不出 80（CJK 与数字间无 \b 边界）。
- L87：`ping\s+(?:一下\s+)?` —— `ping一下baidu.com`（无空格，中文习惯）提不出 host。
- L235：`(?:打印|echo|看一下?|输出)\s+` —— `打印PATH` 同样失效。
- 建议：`\b` 改显式边界 `(?<![0-9A-Za-z])…(?![0-9A-Za-z])`；动词与参数间 `\s+` 改 `\s*`。

### P1-7 file_keyword 贪婪吞掉"的文件" [实测]

- 位置：`lch/extract.py` L62 字符类含 `\u4e00-\u9fff` —— `找叫app.log的文件` → `file_keyword='app.log的文件'`。
- 建议：捕获后剥离尾部 `的文件/文件`，或右侧加锚 `(?=的文件|$|\s)`。

### P1-8 URL 误提取为 path [实测]

- 位置：`lch/extract.py` L164 —— `http://example.com/a/b` → `path='//example.com/a/b'`。
- 建议：`(?<!:)/` 或先剔除 URL 片段。

### P1-9 端口 1900-2099 一刀切当年份排除

- 位置：`lch/extract.py` L25 `(1900 <= val <= 2099)` —— 裸数字兜底下 2049(NFS)、1935(RTMP)、2022 等合法端口被丢。
- 建议：仅在文本含日期语境（年/月/日）时排除。

### P1-10 每个命中重复跑全量提取正则

- 位置：`lch/engine.py` L105-107 + L112 —— `extract_params(text, …)` 在 `_to_hit` 内对**同一文本**逐 hit 执行（~30 个正则 × top_k 最多 10 次）。
- 建议：`query()` 里提取一次，`_to_hit` 只按 `rule.params` 白名单裁剪。

### P1-11 loader 校验缺失 + 加载失败无降级

- 位置：`lch/loader.py` L87-101、L159-171
  - `risk_level` 不校验：拼错时 `RISK_ORDER.get(...,9)` 静默垫底排序；
  - `keywords` 允许为空：规则永不命中且无告警；
  - `keyword_weights` 的键不校验是否存在于 keywords；
  - `weight` 的 `float()` 抛错不带文件/意图上下文；
  - 重复 intent_id 直接 `raise`（L163-166）→ 一个坏分片使整个引擎起不来 / `reload` 失败，没有"跳过坏规则并告警"的宽松模式。另外重复判定与 `enabled=False` 的交互依赖顺序（禁用规则不占 id，但后出现的禁用重复项仍会触发 raise），行为不一致。
- 建议：加载期做轻量 schema 校验并聚合报错；提供 strict/lenient 两档，reload 失败时保留旧规则集并回显错误。

### P1-12 热加载不完整

- 位置：`lch/engine.py` L60-70 —— `reload()` 重新解析 `rules_path`，但 `adapt_path` 只在 `__init__` 解析一次（L50），运行中新增 `config/system_adapt.json` 不生效；也无 mtime 自动检测（若为设计取舍应文档化）。

## 算法级改进路线（贴合纯离线、无强制第三方依赖）

1. **加载期预处理**（一次性）：keywords 经 NFKC+casefold 归一 → jieba `add_word` 注入 → 对每个 keyword 分词缓存 token 集 → 建 token/子串倒排索引。
2. **打分改造**：token 覆盖率 × keyword 权重（加权 TF/coverage），同区间重叠命中取最长匹配去重；总分做规则侧归一后再比阈值；置信引入 Top1-Top2 margin。
3. **兜底层**：无 jieba 时用字符 2-gram Jaccard/覆盖率代替现在的"子串 + 短词双重降权"，天然容忍插字（"内存**的**占用"）。
4. **数据外置**：同义词表、繁简映射表、否定词表放 `resources/dict/`，纯 JSON 数据，随规则热加载。
5. **可选增强**：拼音容错按 jieba 同款懒加载模式接 pypinyin，缺失自动跳过。
