# 变更记录：评审 P3 落地

日期：2026-08-11

## 背景

评审 P0/P1 已落地后，继续完成下一档（原 P2 / 对用户称 P3）：匹配串台、剩余多步 sequence、打包可核对规则版本、文档与测试入口。

## 功能变更

### 1. 匹配器短词降噪（`lch/matcher.py`）

- 长度 ≤2 的纯中文 keyword：基础权重上限 1.5；仅子串命中再 ×0.6；jieba 辅分系数 0.25。
- jieba：长度 ≤2 的 token 仅允许与 keyword **完全相等**，避免「服∈服务」类噪声。
- 单测：`tests/test_matcher.py`。

### 2. 多步规则改为 sequence

| intent | 说明 |
|--------|------|
| `user.whoami` | whoami → id → groups |
| `cron.list` | crontab → /etc/cron.* → timers |
| `env.path.view` | PATH → 分行 → which |
| `sys.disk.du` | 总量 → 一级子目录 |
| `jvm.thread.dump.signal` | kill -3 → jcmd |
| `jvm.gc.log` | 进程参数 → 路径 → jps |
| `java.version` | java → javac → properties |
| `nginx.config.view` | -T → ls → cat |
| `nginx.reload` | sequence: -t → reload；备选 `-s reload` |

其余 `cmd_template` 多为工具互替（ss/lsof、firewalld/ufw），保持候选并列。

### 3. 打包规则指纹（`scripts/build_release.sh`）

- 同步打包 `resources/templates/`。
- `VERSION` 增加 `build_utc`、`rules_sha256_16`、`rules_files`。
- 写出 `resources/RULES_STAMP.json`，便于对照源码与 dist 是否同批规则。

### 4. 文档与测试入口

- `.docs/INDEX.md` 索引。
- `scripts/run_tests.sh`：`PYTHONPATH=. python -m unittest discover -s tests -v`。
- 逻辑梳理：`.review-ll/评审P3落地-逻辑梳理.md`。
